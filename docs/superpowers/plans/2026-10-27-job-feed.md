# Job Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A personal job-feed website (static, on Vercel) fed by a 30-minute GitHub Actions pipeline that aggregates ATS, community-list and aggregator postings and pushes matching new ones to the user's iPhone via ntfy.

**Architecture:** TypeScript pipeline (adapters -> normalize -> classify -> dedupe -> diff -> publish -> alert) writes `jobs.json` + `state.json` to an orphan `data` branch; a Vite + React site fetches `jobs.json` from raw GitHub at runtime and filters client-side. No database.

**Tech Stack:** Node 24, TypeScript, tsx, Vitest, zod, yaml, Vite, React, GitHub Actions, Vercel, ntfy.sh.

**Spec:** `docs/superpowers/specs/2026-10-27-job-feed-design.md`

## Global Constraints

- Node 24, ESM (`"type": "module"`), TypeScript strict. Pipeline run command: `tsx pipeline/run.ts`.
- Target grad year is **2027**; 2026 postings are shown but excluded from alerts; `null` year is alert-eligible (spec §5).
- Internships, co-ops and apprenticeships are **dropped** by `classify()` (spec §1 scope; rule defined in Task 4).
- Cron every 30 minutes; fetch timeout 25 000 ms; descriptive User-Agent `job-feed/1.0 (personal job aggregator)`.
- A failed source carries its previous jobs over unchanged and is marked `stale`; a source returning more than 60% fewer jobs than last run counts as failed (spec §6).
- Closed jobs are kept 7 days with `closedAt` set, then dropped.
- Alerts: first run silent; more than 5 matches in a run -> one digest; ntfy failure leaves ids un-alerted for retry; default rule in `config/alerts.yml` exactly as in spec §7.
- Secrets only in GitHub Actions secrets / local `.env` (gitignored): `NTFY_TOPIC`, optional `ADZUNA_APP_ID`, `ADZUNA_APP_KEY`, `JOOBLE_KEY`. Never in `jobs.json` or committed files.
- Snippet <= 400 plain-text characters. `localStorage` access always in try/catch.
- Repo is public (raw GitHub data URL). Commits are made at the end of each task.

## Review Focus

Failure modes the spec implies but does not pin down, most likely first. Each has its test in the named task.

1. **"CA" means California, not Canada.** "San Francisco, CA" must never match Canada. Location parsing treats only "Canada", a Canadian-city list, and `, ON|BC|AB|QC` as Canada. (Task 3)
2. **"Remote - US" is not Canada-eligible**, while plain "Remote" and "Remote in Canada" are. (Task 3, Task 13)
3. **Internships masquerading as new-grad:** "Software Engineer Intern, Summer 2027" and "Co-op" titles are dropped, not tagged `gradYear 2027`. (Task 4)
4. **A source returns HTML, `{}`, or an empty list on a bad day.** It must be marked failed/stale and its previous jobs carried over; nothing is mass-closed or alerted. (Task 12)
5. **Alert delivery edge cases:** non-ASCII titles (e.g. "Ingénieur logiciel – Nouveau diplômé") must survive; a missing `NTFY_TOPIC` skips alerts with a warning instead of crashing. (Task 13). The site must also render an empty/failed `jobs.json` fetch as a message, not a blank page. (Task 17)
